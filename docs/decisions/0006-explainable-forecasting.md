# ADR-0006: explainable statistical forecasting, no ML runtime

- **Status:** Accepted (2026-09-08, Phase 2)
- **Context:** PS-26033 explicitly requires AI demand forecasting. The demo has no real order history, and a black-box model (Python service, trained weights, hosted inference) would be unverifiable by judges, unexplainable to farmers/operators, and disproportionate to 16 weeks of demo data.
- **Decision:** `packages/forecast` implements a transparent statistical method in pure TypeScript: weighted moving average (weights 1–4) + damped least-squares linear trend (60% damping) + multiplicative 4-week seasonal index, with the confidence band sized by the model's MAPE (clamped 8–35%). Demo history is generated by a seeded PRNG (fixed anchor week) so outputs are fully deterministic and testable. Forecast demand is compared against geofenced supply (bags of paddy within 100 km) to drive the "reserve early" nudge.
- **Consequences:** Every forecast can be reproduced by hand and defended in Q&A; zero new dependencies and zero inference cost. It will underfit genuinely complex demand — the package API (`history[] → ForecastResult`) is the stable seam: swap in a better model at pilot without touching routes or UI.
- **Alternatives rejected:** OR-Tools/Prophet via a Python sidecar (deployment burden, unexplainable); linear regression alone (ignores seasonality); hosting a third-party forecasting API (external dependency for a demo).
